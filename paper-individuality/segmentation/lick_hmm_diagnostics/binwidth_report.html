Choosing the Lick Bin Width

At one frame per bin the trace is binary and both Poisson states land on the same rate, so every fit collapses. Anything from two frames up segments — the question is only how coarse to go.

50 ms is not on the grid

One frame at 30 Hz is 33.3 ms, so integer binning offers 33.3, 66.7, 100, 133 and 200 ms — there is no 50. The lowest width above the current setting is 66.7 ms, and that is what the sweep below tests. On the 60 Hz two-camera cohort 50 ms is exactly 3 frames, so that set will need its own answer.

Two corrections to what I told you earlier

bits_LL is per bin, not per unit time. Comparing it across bin widths compares likelihoods of different data, which is not a valid model-selection criterion — a 200 ms bin is a different observation than a 33 ms one. I earlier said “bits_LL picks 100 ms”; treat the curve below as descriptive of where the 2-state model explains most per observation, not as a decision rule.

The “COLLAPSED” labels on some 200 ms rows are a bug in my plot, not a real collapse. I passed the frame rate rather than the bin rate to the assessment, so the dwell-time screen was scaled by the wrong factor and mis-fired. The figure contradicts the label: those rows visibly segment.

A single frame holds either 0 or 1 lick, so both states converge on the same near-zero rate and there is nothing for the likelihood to separate. The moment a bin can hold two licks the states split apart, and they stay split at every coarser width.

What to use

67 ms — the floor
Fixes the collapse in all six sessions and gives the best onset precision (~19 ms RMS). Lowest information per bin of the working widths, and the least margin if a session licks more sparsely than these.
100 ms — the safe choice
At or near the per-bin optimum for the faster lickers, ~29 ms RMS onset error, which already matches the whisker HMM's ~33 ms lag jitter. Beyond this, extra precision is not usable in the combined syllables anyway.
per-session width from lick rate
If the ~0.25–0.34 licks-per-bin alignment holds on the full set, the width could be set from each session's own rate rather than fixed globally. Worth checking on all ~70 failing sessions before adopting.
